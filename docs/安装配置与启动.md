# 安装、配置、登录与启动

本文对应 0.3.1 已实现接口。命令在解压后的项目根目录执行，适用于 macOS/Linux；Windows 未适配。

## 1. 环境与安装

需要 Python 3.7+、Node/npm，以及可以访问钉钉与 Codex 服务的网络。建议新部署使用维护中的 Python/Node LTS。运行代码不依赖第三方 Python 库；npm 的开发检查工具要求 Node >=18.18。

安装本项目核对过的 CLI 版本：

```sh
npm install -g dingtalk-workspace-cli@1.0.65 @openai/codex@0.163.0
node --version
python3 --version
command -v dws
command -v codex
dws version
codex --version
```

`dws` 是 dingtalk-workspace-cli 安装出来的命令，不是其他钉钉助手包。安装会下载平台二进制。已安装可跳过；更高版本应重新核对命令兼容性。

使用 nvm 时，先激活安装 CLI 的 Node 版本。command not found 说明 PATH 或安装不正确；无需复制别人的登录文件。

## 2. 钉钉登录和 profile

```sh
dws auth login
```

按浏览器提示使用自己的钉钉账号授权。终端保持运行直到完成。SSH/无头环境改用 `dws auth login --device`。国际版增加 `--intl`；后续业务按 profile 自动选择区域。

默认示例不加 `--recommend`：该选项会批量授权推荐权限。根据实际缺少的消息/事件/待办权限确认授权范围；本项目不处理 OA 审批。

```sh
dws profile list --format json
```

从结果找到自己的组织和账号，复制稳定 `profile`（corpId:userId）。多个账号不要取第一条。以下变量仅用于当前终端，替换为自己返回的值：

```sh
EARS_PROFILE='实际corpId:实际userId'
dws auth status --profile "$EARS_PROFILE" --format json
dws contact user get-self --profile "$EARS_PROFILE" --format json
```

检查 authenticated、token_valid 以及本人/组织信息。profile list 不刷新 token；auth status --readonly 只是快照，不能证明在线鉴权成功。

## 3. 本人 OpenID 与群 ID

profile 里的员工 userId 与事件使用的 openDingTalkId 不同，不能互相替代。

若本人资料返回 openDingTalkId，核对后使用该值；当前核对的 get-self 接口只返回员工 userId，并不保证包含 OpenID。可在企业开通该能力的前提下，使用自己的手机号或钉钉号查询：

```sh
dws contact user get-open-dingtalk-id --keyword '自己的手机号或钉钉号' --profile "$EARS_PROFILE" --format json
```

该接口有企业灰度和频次限制。返回 ability_not_full_open 时，需由企业开通或从已核验的本人 IM 身份资料取得 OpenID；项目不能绕过限制，也不能猜造 ID。尚未取得本人 OpenID 时先停止配置，不填写别人的 ID。

查关注群：

```sh
dws chat +chat-search --query '关注群名称' --profile "$EARS_PROFILE" --format json
```

核对名称、成员等信息后，取正确群的 openConversationId。相似/同名群不能取首个结果；hasMore=true 表示候选未读全。所有查询与之后的写入必须用同一个 profile。

## 4. Codex 登录

```sh
codex login
codex login status
```

按提示使用自己的 ChatGPT 身份登录并确认状态。无头环境可用 `codex login --device-auth`，前提是账号或工作区允许设备码登录。还需要账号有相应 Codex 权限和额度。

钉钉与 Codex 是两套独立认证。项目自动启动 `codex app-server --stdio`，无需另起一个服务。消息会交给云端模型整理，不是完全离线处理。[Codex 认证官方说明](https://learn.chatgpt.com/docs/auth)。

## 5. 写配置

```sh
python3 -m backend init --output config.local.json
```

命令只创建占位模板，不登录、不启动监听、不覆盖已有配置。编辑 config.local.json，例如：

```json
{
  "profile": "corpId:userId",
  "self_id": "已经核验的本人openDingTalkId",
  "display_name": "我的称呼",
  "groups": [
    {
      "id": "已经核验的群openConversationId",
      "name": "设计团队"
    }
  ],
  "server": { "port": 8766 },
  "paths": {
    "state_dir": "./data",
    "output_dir": "./data/output"
  },
  "commands": { "dws": "dws", "codex": "codex" },
  "batch": {
    "direct_seconds": 30,
    "group_seconds": 300,
    "trigger_count": 20,
    "max_messages": 50
  }
}
```

| 字段 | 填写规则 |
| --- | --- |
| profile | profile list 返回的真实 corpId:userId |
| self_id | 本人开放钉钉号 ID，用于过滤本人消息，不能使用员工 userId |
| display_name | 自己的称呼，仅作为 AI 输入的 context 数据，不拼入系统提示词 |
| groups | 关注群数组；每项包含真正监听的 `id` 和网页显示的 `name`，群 ID 不能重复 |
| server.port | 1–65535 的可用端口；仅监听 127.0.0.1，不允许配置为公网绑定 |
| paths.state_dir | 数据库、会话映射、日志目录；不同身份必须使用不同目录 |
| paths.output_dir | 状态文件与摘要目录；换身份时也应使用独立目录 |
| commands.dws / codex | 命令名或实际可执行文件路径；后台推荐绝对路径 |
| batch | 正整数秒数及阈值，trigger_count <= max_messages <=500 |

所有相对路径以**配置文件所在目录**为基准。必填身份不能空缺；未知字段、重复 JSON 键、占位身份和非法数字会报错。JSON 不能写注释或尾随逗号。

配置不包含 access token、refresh token 或 AppSecret，这些未知字段会被拒绝。模板 config.example.json 可以分享，config.local.json 不要分享。

### 在面板中管理关注群

打开本地面板的“关注群”区域，点击“添加关注群”即可查询已加入的群。选择框支持按群名称搜索与多选；每个已选群会显示为可移除标签。下拉面板最大高度为 400px，候选较多时在面板内滚动。点击“保存关注群”后，群列表会写入本机 `config.local.json`，重启服务后开始或停止对应群的监听。

## 6. 检查与前台启动

```sh
python3 -m backend --config config.local.json doctor
python3 -m backend --config config.local.json run
```

参数顺序：全局 --config 放在 doctor/run/service 前面。doctor 检查 CLI、选定身份的钉钉认证、本人 userId、Codex 登录、目录可写性、数据归属和端口，不创建订阅或发送消息。CLI 未返回本人 OpenID 时会明确警告需要手动核验，不把缺字段说成已验证。

若已有服务占用端口，doctor 会报端口不可绑定；先检查是否已有实例，不要再起第二份。诊断退出码 0 表示没有阻断错误，仍需阅读 warning；不保证实时事件一定投递。

浏览器打开配置对应的地址，默认 <http://127.0.0.1:8766/>。前台按 Ctrl+C 停止。也可执行 `python3 ears.py --config config.local.json run`。root 下 ears.py 仅是兼容入口，业务代码在 backend/。

程序启动后读取配置中的 profile；不会因为你后来切换 DWS 默认账号就自动换身份。改配置需要停止并重启。

## 7. 登录态如何复用

| 内容 | 归谁管理 | 默认位置/使用方式 |
| --- | --- | --- |
| 钉钉登录 | DWS CLI | 默认配置根目录 ~/.dws，凭据也可能使用系统凭据存储；通过相同 --profile 调用 |
| Codex 登录 | Codex CLI | ~/.codex 下的认证文件或系统凭据存储，取决于 Codex 配置 |
| 消息与草稿 | 本项目 | paths.state_dir 下的 SQLite，不是登录凭据 |

同一个系统用户下通常不必每次重新登录。自动刷新仍可能因撤销授权、过期、权限或系统钥匙串不可用而失败；遇到真实认证错误重新授权，不循环重试。

登录时设置 DWS_CONFIG_DIR 或 CODEX_HOME 的，后台也需要相同环境变量。不要修改 HOME 冒充别的账号，不要 sudo 运行项目。其他人必须自己登录，不复制 ~/.dws、~/.codex、认证包或钥匙串。

## 8. macOS 后台与登录启动

确认前台实例退出，在已激活正确 Python/Node 环境的终端执行：

```sh
python3 -m backend --config config.local.json service --install
```

生成 launchagent.local.plist，并安装到本人 ~/Library/LaunchAgents/com.codex.dingtalk-ears.plist 后加载。去掉 --install 则只生成本地文件；可用 --output 指定生成位置，--python 指定实际 Python 路径。

```sh
launchctl print "gui/$(id -u)/com.codex.dingtalk-ears"
launchctl bootout "gui/$(id -u)/com.codex.dingtalk-ears"
launchctl bootstrap "gui/$(id -u)" "$HOME/Library/LaunchAgents/com.codex.dingtalk-ears.plist"
```

分别用于查看、停止、停止后的重新启动。已有同名服务安装会报错，先停止再安装；不会自动杀掉已有服务。生成输出文件也不覆盖：若 launchagent.local.plist 已存在，使用 --output 指定一个新的 .plist 路径。

启动项保存绝对项目/配置/解释器路径、安装时的 PATH 及显式 DWS_CONFIG_DIR/CODEX_HOME；不保存认证 token。npm 的 CLI 包装器需要 Node，PATH 必须包含对应 Node bin。移动项目、换解释器或 nvm 版本后重新生成并安装。

登录后运行，关闭浏览器或锁屏不影响后台；接电时 caffeinate -s 防止自动睡眠，屏幕可熄灭。普通合盖、注销、关机和断网仍会中断，事件不保证历史补发。未配置无限重启，异常退出先查日志再启动。

Linux 使用前台 run 或自行配置用户服务；service 命令仅支持 macOS。

## 9. 旧数据迁移

先停旧服务，备份 queue.db、panel.db（运行中使用 SQLite backup API，不能只复制主文件忽略 WAL）。配置 state_dir 指向正确旧目录，output_dir 指向希望保留摘要的位置。

无 identity.json 的旧数据需要明确认领一次：

```sh
python3 -m backend --config config.local.json run --adopt-state
```

只在确认数据库属于同一账号和群时使用。认领后写入身份标记，之后普通 run 即可。标记身份不同会拒绝启动，应使用新的空数据目录；不要删除标记强行混用。

## 10. 接收状态与排错

- 网页打开只说明 HTTP 服务可访问；订阅 ready 只说明订阅阶段就绪。degraded/断开会明确显示连接异常。
- 用 `dws event status --profile "$EARS_PROFILE" --format json` 核对源和消费者；日志在 state_dir 下 direct.log、at.log、ued.log 和 agent/appserver.log，后台另有 host.stdout.log、host.stderr.log。
- 请同事发送一条新的普通消息或 @消息，核对来源、时间及本次进程的实际接收计数；本人消息过滤，跨渠道重复消息合并。后台重启计数归零，已有数据仍保留。
- 默认单聊/@我 30 秒、普通群 5 分钟或达到阈值后整理。先收到消息不等于 AI 已整理。
- 待办和回复仅确认后写入；超时/结果不明先在钉钉核对，不自动再发。
- 认证 401/403 先核对 profile、登录和授权范围；命令找不到检查 commands/PATH；App Server 错误看日志，不清空数据库求恢复。
- DWS 订阅失败不无限重试，不通过删除 SDK 保护记录绕过限制。离线期间事件遗漏不能由配置重构保证修复。

## 11. 开发与分享

见 README：npm ci + Python 开发依赖后运行 `python scripts/check.py`。单独 CSS 检查为 npm run lint:css，自动修复为 npm run lint:css:fix，前端格式检查为 npm run format:check。Python 运行兼容测试为 `python3 -m unittest discover -s tests -v`。

```sh
python3 -m backend share --output ../dingtalk-ears-share.tar.gz
```

只分发白名单源码与通用文档；接收者解压后从第 1 步使用自己的账号配置。不要发送整个含私有配置的工作目录。

CLI 参数核对于 DWS 1.0.65、Codex 0.163.0；更换版本需复核。钉钉源码入口：[DingTalk Workspace CLI](https://github.com/DingTalk-Real-AI/dingtalk-workspace-cli)。
